# Git-Release-Notifier 🤖

Telegram-бот для отслеживания новых релизов на GitHub.  
Он автоматически проверяет добавленные репозитории и присылает уведомления о каждом новом релизе.

## Возможности

- Добавление публичных GitHub-репозиториев по ссылке
- Просмотр последних трёх релизов для каждого репозитория
- Автоматическая проверка раз в час (настраивается) и мгновенные уведомления о новых релизах
- Ручная проверка выбранных репозиториев командой `/check`
- Удобное управление списком: редактирование URL, удаление, пагинация
- Постоянное хранение подписок в JSON-файле
- Ротация логов с ограничением размера
- Опциональная поддержка GitHub-токена для повышения лимитов API и доступа к приватным репозиториям

## Предварительные требования

- **Python 3.10** или новее
- Установленные пакеты: `aiogram`, `aiohttp`, `python-dotenv` (см. `requirements.txt`)
-- **Telegram Bot Token**, полученный у [@BotFather](https://t.me/BotFather)

## Быстрый старт

1. Клонируйте репозиторий и перейдите в папку проекта:
   ```bash
   git clone <url-репозитория>
   cd Git-Release-Notifier
   ```

2. Установите зависимости:
   ```bash
   pip install aiogram aiohttp python-dotenv
   ```

3. Создайте файл `.env` в корне проекта и укажите токен бота, а также (при желании) GitHub-токен:
   ```
   BOT_TOKEN=123456:ABC-DEF1234ghIkl-zyx57W2v1u123ew11
   GITHUB_TOKEN=ghp_yourGitHubTokenHere
   ```
   `GITHUB_TOKEN` — необязательный параметр. Если его не задать, бот будет работать с лимитом 60 запросов/час к GitHub API.

4. Запустите бота:
   ```bash
   python main.py
   ```

Бот начнёт опрос серверов Telegram. Остановить можно нажатием `Ctrl+C` — произойдёт корректное завершение фоновых задач.

## Конфигурация

Все параметры собраны в файле `core/config.py`. Основные настройки:

| Параметр                | По умолчанию         | Описание                                                                                     |
|-------------------------|----------------------|----------------------------------------------------------------------------------------------|
| `BOT_TOKEN`             | (пусто)              | Токен Telegram бота. **Обязателен**, читается из `.env`                                     |
| `GITHUB_TOKEN`          | (пусто)              | Персональный токен GitHub. Повышает лимит запросов до 5000/час и даёт доступ к приватным репозиториям (при наличии прав). Задаётся в `.env` |
| `SUBSCRIPTIONS_FILE`    | `subscriptions.json` | Файл, в котором хранятся подписки пользователей                                              |
| `CHECK_INTERVAL_SEC`    | `3600`               | Интервал (в секундах) полного цикла фоновой проверки всех репозиториев (1 час)               |
| `API_DELAY_SEC`         | `3.0`                | Задержка между запросами к GitHub API для соблюдения лимитов (секунды)                       |
| `REPOS_PER_PAGE`        | `10`                 | Количество репозиториев на одной странице в списке                                          |
| `LOG_DIR`               | `logs`               | Папка для файлов логов                                                                      |
| `LOG_FILE`              | `bot.log`            | Имя файла логов                                                                              |
| `LOG_MAX_BYTES`         | `5 * 1024 * 1024`    | Максимальный размер одного лог-файла (5 МБ)                                                  |
| `LOG_BACKUP_COUNT`      | `3`                  | Количество ротируемых архивов логов                                                         |

> Чтобы изменить значения, отредактируйте константы в `core/config.py`.  
> Прямое изменение через переменные окружения (кроме токенов) не предусмотрено.

## Использование

После запуска бот ожидает команды и нажатия кнопок в Telegram.

### Основные команды

- `/start` – приветственное сообщение и главное меню.
- `/help` – краткая справка по возможностям.
- `/check` – ручная проверка всех ваших репозиториев с указанием времени последней проверки.

### Главное меню (постоянная клавиатура)

- **📋 Мои репозитории** – показывает список отслеживаемых репозиториев с постраничной навигацией.
- **➕ Добавить репозиторий** – запускает диалог добавления нового репозитория.

### Управление репозиториями

**Добавление**  
Нажмите «Добавить репозиторий» и отправьте полную ссылку на публичный GitHub-репозиторий, например:  
`https://github.com/psf/requests`

Бот проверит существование репозитория, запишет последний известный релиз и добавит его в ваш список. Если указан `GITHUB_TOKEN`, можно добавлять также приватные репозитории, доступные этому токену.

**Просмотр**  
В списке репозиториев нажмите на название. Откроется детальный вид:
- ссылка на репозиторий;
- последние три релиза (тег, название, дата);
- дата последней проверки.

Кнопки в детальном виде:
- **✏️ Изменить** – сменить URL репозитория (с повторной валидацией).
- **🗑 Удалить** – удалить репозиторий после подтверждения.
- **⬅️ Назад** – вернуться к общему списку.

**Ручная проверка конкретного репозитория**  
В представлении `/check` рядом с каждым репозиторием есть кнопка 🔄 — она принудительно запрашивает свежие данные и обновляет кеш релизов.

### Фоновый мониторинг

Бот автоматически проверяет все уникальные репозитории раз в час (по умолчанию).  
Если обнаружен новый релиз (его ID больше сохранённого), подписчику приходит уведомление в личные сообщения.  
Уведомление содержит название репозитория, тег, ссылку на релиз и первые 500 символов описания.

## Логирование

Логи записываются одновременно в консоль и в файл `logs/bot.log`.  
Ротация настроена: при достижении 5 МБ создаётся новый файл, а старые архивируются (хранятся до 3 файлов).  
Уровень логирования — `INFO`. При ошибках в консоль и лог попадает полная трассировка.

## Ограничения

- **Лимиты GitHub API**  
  - Без токена GitHub действует ограничение **60 запросов в час** для одного IP. При большом количестве репозиториев или частых ручных проверках возможна блокировка.  
  - Если в `.env` задан `GITHUB_TOKEN`, лимит возрастает до **5000 запросов в час**.  
  - Токен также позволяет отслеживать приватные репозитории, к которым у токена есть доступ. Получить токен можно в [настройках GitHub](https://github.com/settings/tokens).

- **Хранение подписок** – все данные хранятся локально в файле `subscriptions.json`. При необходимости делайте резервные копии.
- **Нельзя запускать несколько экземпляров бота** – это приведёт к дублированию проверок и уведомлений.
